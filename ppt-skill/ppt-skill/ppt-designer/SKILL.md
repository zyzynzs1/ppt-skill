# PPT 设计生成技能

## 〇、轻量路由（动手前 10 秒，命中即执行）

| 请求形态                 | 路由                                                         | 前提                    | 产出         |
| ------------------------ | ------------------------------------------------------------ | ----------------------- | ------------ |
| 只有主题/模糊想法        | **主题生成**：走第一~四阶段，访谈从宽                        | 用户能回答受众/目的两问 | 全新 .pptx   |
| 有文档/PDF/大纲/旧稿     | **文档生成**：先做素材充分性测试（见三-4），再走第一~四阶段  | 素材可读                | 全新 .pptx   |
| 已有 .pptx 要美化/改内容 | **编辑路由**：先解析原稿结构与版式，仅允许改色/改字/重排内容，不重画整体风格 | 原文件可打开            | 修改版 .pptx |

**Hard rule — 禁止路由菜单**：请求已命中表中一行就直接执行，不得再问用户"你想要哪种方式"。
**Hard rule — 前提不满足就停**：缺前提（如编辑路由拿不到文件）明说原因并停止，不发明替代路线。

## 一、何时使用 / 何时不使用本技能

**适用**：用户提到「ppt」「幻灯片」「汇报」「路演」「slides」等关键词，或明确要求制作/美化/生成演示文稿，目标是**结构化信息图风格的技术商务汇报**（方案汇报、产品介绍、投标响应、培训材料、咨询报告）。

**不适用**（明确告知用户并建议改道）：

- 需要演讲者视图、逐页计时、现场互动的演讲型 deck（建议 HTML 网页 PPT）
- 大段数据报表、需多人协作编辑的内容（建议 Excel/飞书/Notion）
- 强艺术表现/逐帧动画的发布会级视觉（需设计师介入）

## 二、术语表（一词一义，全包唯一含义）

| 术语                  | 含义                                                       | 标记    |
| --------------------- | ---------------------------------------------------------- | ------- |
| **令牌**              | 颜色/字号/间距参数，全部取自 `design-tokens.md`            | binding |
| **页面任务**          | 这一页必须为读者做的一件事，先于任何版式决定               | binding |
| **观点**              | 结论式页标题，一句可独立成立的判断                         | binding |
| **支撑证据**          | 让观点成立的内容：机制（L1）/参数（L2）/数据（L3）         | binding |
| **维度 D1-D9**        | 技术/方案汇报的九个必备内容维度（见三-1）                  | binding |
| **深度层 L1/L2/L3**   | 机制层/参数层/数据层（见三-2）                             | binding |
| **页面规格卡**        | 逐页填写的内容-设计联合规格（见 `templates/page-spec.md`） | binding |
| **原型**              | 页面版式骨架（A-F，见第七节）                              | 参考    |
| **组件**              | 徽章/卡片/流程链等可视化件（见第六节）                     | 参考    |
| **参考（Reference）** | 初稿性质，执行者可调整替换，无需向上报备                   | 参考    |

## 三、内容深度规范（本技能的核心纪律）

> 视觉统一只解决"好看"，本规范解决"有料"。**内容缺失不允许静默发生——每个维度必须显式确认「纳入」或「排除」。**

### 1. 内容维度核对表（第一阶段访谈必做）

| #    | 维度                        | 典型页面形态             | 缺素材时的处理              |
| ---- | --------------------------- | ------------------------ | --------------------------- |
| D1   | 现状与痛点                  | 对比表、数据指标         | 代拟须标【待确认】          |
| D2   | 总体架构 / 技术架构         | 分域架构图（C4）         | 必须画出，不得跳过          |
| D3   | 核心流程（业务/数据流）     | 阶段带+流程链（C4）      | 必须画出，不得跳过          |
| D4   | 网络/部署拓扑（如涉及系统） | 拓扑图（C4）             | 用户确认不适用才可排除      |
| D5   | 组织与人员体系              | 组织架构图、角色卡（C5） | 须落到"角色—职责—动作"      |
| D6   | 培训与考核机制              | 流程链+要点卡            | 同上                        |
| D7   | 测试/质检/误差控制机制      | 阈值表、控制流程         | 涉及"准确性/质量"的领域必填 |
| D8   | 数据合成/统计/安全合规      | 校验规则表、指标块       |                             |
| D9   | 关键功能截图与界面介绍      | 截图位+图注（E 页）      | 无截图时用占位框并告知补图  |

**排除规则**：用户明确说"不适用/没有"→ 在排除表写「排除：原因」；用户没提到 → **必须追问**，不得默认跳过。

### 2. 深度三级标准（每个核心论点钻到底）

```
L1 机制层：是什么、怎么运转（流程/架构/角色分工）
L2 参数层：具体阈值、规则、数量、时限、比例（"双评差值≤2 分转仲裁"，不是"有误差控制"）
L3 数据层：支撑证据——历史数据、性能指标、案例、资质编号
```

**判定**：L2 全稿为 0 处 = 深度不合格，返工；关键章节（D2/D3/D7）必须同时有 L1+L2。

### 3. 观点—支撑配对规则

每页 = 1 个观点 + 支撑证据。写「全流程质量控制」→ 页面必须出现：控制环节清单 + 至少 1 个具体阈值/规则 + 责任角色；写「性能有保障」→ 必须有具体指标数字。无数据时用机制细节补位，页脚标【数据待补充】。

### 4. 素材充分性测试（文档生成路由必做）

读完用户素材后自检：哪些断言缺支撑？——素材内能答的用素材；素材答不了且属外部可查证事实的，列入【待确认】清单一次性问用户；**素材没说的，禁止编造补齐**。封闭语料不得自行外扩。

## 四、工作流程（门禁状态机，严格按 Stage 顺序）

> 每个 Stage：🚧 进入条件 → 执行 → ✅ Checkpoint。Checkpoint 不过，只报阻塞项并退回本 Stage 修复，**禁止带病进入下一 Stage**。

### Stage 1 需求澄清

🚧 用户提出任何 PPT 请求。
执行：① 轻量路由命中确认；② 六问——主题与目的/场合时长/内容来源/硬约束/页数章节/**维度核对表**（三-1）；③ 输出「需求确认摘要」。
✅ 用户确认摘要，且维度表每行都有「纳入/排除+素材情况」。

### Stage 2 内容策划（角色：策划者）

🚧 Stage 1 通过。
执行：① 无大纲时用叙事弧搭骨架：钩子1页→定调1-2页→主体3-5页（D2-D9 按确认结果展开）→转折1页→收束1-2页；② **逐页填写页面规格卡**（模板见 `templates/page-spec.md`，内容深浅的抓手，禁止跳过）；③ 汇总三张表——规格卡组、深度映射表（标注每页覆盖 L1/L2/L3，L2 全稿 ≥5 处）、维度排除表。
✅ 三张表经用户确认。绘制阶段不得回改规格卡内容，内容问题一律退回本 Stage。

### Stage 3 设计生成（角色：绘制者）

🚧 Stage 2 三表确认。
执行：① 生成前必读 `design-tokens.md` 第 0 节 Pre-flight；② 严格按每页规格卡的「原型+组件」选型，用 `scripts/pptx_helpers.py` 生成，**禁止发明 tokens 之外的值**；③ 素材按契约放 `images/`，命名 `{页码}-{语义英文}.{ext}`。
✅ `python scripts/validate_deck.py 文件.pptx` 通过（视觉层）。

### Stage 4 质检交付（角色：质检者，只挑错不创作）

🚧 Stage 3 通过。
执行：① P0 内容检查（第九节 C1-C5）——对照三张表逐页核对，发现内容缺/浅退回 Stage 2；② P1 视觉检查（V1-V7）；③ 逐页导出图片目检（溢出/对齐/遮挡）。
✅ 全部通过 → 交付文件并附「维度覆盖情况 + 深度分布 + 遗留【待确认】清单」。

## 五、设计系统（强制摘要）

> 全部令牌见 `templates/design-tokens.md`（Pre-flight 必读）；备选色板整组替换、禁止单改。

- 画布 16:9，10in × 5.625in；边距左右 0.5in；内容区 y 0.85~5.3in；页脚基线 y=5.44in（文档名 + 两位页码）
- 默认蓝金：INK #12263F / NAVY #0F2B52 / PRIMARY #0068B7 / STEEL #4A6B99 / 浅蓝阶梯 / GOLD #C9983B 家族 / CYAN #37B6E6；整页底色 #EFF5FB；金色面积 ≤5%
- 字体全稿唯一：微软雅黑；字号阶梯 32/17/12/9/8pt
- 骨架：淡蓝底 → 主蓝竖条+结论式标题(+导语) → 内容区 → 页脚

## 六、组件规范（摘要）

> 参数见 `templates/design-tokens.md` 第 5 节。

编号徽章 / 信息卡片 / 对比表 / 流程链 / 架构分域框 / 数据指标块 / 结论条 / 截图位，8 大组件全稿统一，一律走 helpers 函数。
**深度提示**：规则类内容用「规则表」（写具体阈值，禁写"等/若干"）；组织/培训类落"角色—职责—动作"三要素；每张截图配一句"此图证明什么"。

## 七、页面原型（摘要）

> 坐标见 `templates/page-archetypes.md`，选型时读取对应章节。

A 封面 / B 目录 / C 内容页（C1 三列卡片、C2 左右分栏、C3 上卡下表、C4 全幅流程/架构、C5 两栏对照）/ D 章节过渡 / E 数据成果页 / F 结尾页

## 八、写作规范

1. 标题即结论（判断句，禁「XXX介绍」）；2. 要点动词开头、一行一条、≤22 字，宁拆页不缩字；3. 参数必具体（写阈值写数字）；4. 无法确认标【待确认】，严禁编造；5. 术语全稿一致；6. 单页要点 ≤12 条。

## 九、质量检查清单

### 🔴 P0 · 内容与深度（先查这层）

| #    | 现象                         | 根因            | 做法                                         |
| ---- | ---------------------------- | --------------- | -------------------------------------------- |
| C1   | 架构图/拓扑图/流程图整章缺失 | 默认跳过未追问  | 对照维度表逐行确认；缺失须能出示用户排除记录 |
| C2   | 机制页无规则参数（L2=0）     | 停在机制层      | 关键章节 D2/D3/D7 必须 L1+L2；阈值写数字     |
| C3   | 标题喊结论、正文无支撑       | 观点-支撑未配对 | 每页自问：论据在页面哪里？找不到就补         |
| C4   | 组织/培训页只画框无职责      | 三要素不全      | 角色—职责—动作逐框核对                       |
| C5   | 截图页只贴图无证明点         | 截图当装饰      | 每图一句"此图证明什么"+图注                  |

### 🟡 P1 · 视觉与规范

| #    | 现象                     | 做法                       |
| ---- | ------------------------ | -------------------------- |
| V1   | 同类卡片跨页不一致       | 全部走 `card()/card_row()` |
| V2   | 调色板外颜色             | 必跑 `validate_deck.py`    |
| V3   | 文本溢出/遮挡            | 导出图片逐页目检           |
| V4   | 混用第二中文字体         | 保留 `qn('a:ea')` 行       |
| V5   | 页脚缺失/页码不一        | 100% 走 `page_skeleton()`  |
| V6   | 截图拉伸/文字被裁        | 只用标准比例槽位           |
| V7   | 标题非结论式/金色超 2 处 | 对照 tokens 自查           |
