# PPT 设计生成技能

&gt; **第一性原则：内容深度 &gt; 视觉统一。** 本技能的首要产出是"有论证深度的内容"，视觉系统（第五节起）只是内容的承载。任何视觉规则都不得牺牲内容完整性。

## 〇、轻量路由（动手前 10 秒，命中即执行）

| 请求形态 | 路由 | 前提 | 产出 |
|---|---|---|---|
| 只有主题/模糊想法 | **主题生成**：走第一~四阶段，访谈从宽 | 用户能回答受众/目的两问 | 全新 .pptx |
| 有文档/PDF/大纲/旧稿 | **文档生成**：先做素材充分性测试（见二-4），再走第一~四阶段 | 素材可读 | 全新 .pptx |
| 已有 .pptx 要美化/改内容 | **编辑路由**：解析原稿 → 提取事实清单（内容零丢失）→ 重构叙事 → 重排 | 原文件可打开 | 修改版 .pptx |

**Hard rule — 禁止路由菜单**：命中一行直接执行，不得再问"你想要哪种方式"。前提不满足就明说并停止，不发明替代路线。

## 一、何时使用 / 何时不使用

**适用**：「ppt/幻灯片/汇报/路演/slides」等关键词，或明确要求制作/优化演示文稿，目标是结构化信息图风格的技术商务汇报。
**不适用**（明确告知并建议改道）：演讲者视图/现场互动型 deck（用 HTML 网页 PPT）；大段数据报表/协作编辑（用 Excel/飞书）；发布会级艺术视觉（需设计师）。

## 二、内容生产线（核心，Stage 2 逐条产出）

### 1. 沟通契约（先回答，一句话即可）
受众是谁？他们听完要**知道什么、相信什么、做什么**？核心信息（全稿一句话）？阅读方式（演讲伴随 / 独立阅读）？——所有页面围绕这个契约推进。

### 2. 内容模式（五选一，决定"怎么论证"，与视觉无关）

| 模式 | 论证骨架 | 适用 |
|---|---|---|
| **金字塔** | 结论先行→分论点→论据；每页标题即结论 | 决策支持、方案汇报、投标 |
| **问题-解决** | 痛点→根因→方案→效果 | 产品介绍、立项 |
| **叙事弧** | 情境→冲突→转折→收束 | 路演、案例 |
| **教学分解** | 概念→分解→步骤→练习 | 培训课件 |
| **中性简报** | 主题平铺、等权完整、可检索 | 状态汇报、参考资料 |

### 3. 材料偏离度（用户确认，默认"平衡"）
**贴近原稿**（保结构保措辞，仅调清晰度）/ **平衡重构**（重组叙事，保留全部实质内容）/ **自由重组**（可扩结构加过渡）。**铁律：无论多自由，事实不外扩**——原稿没有的数据/资质禁止编造。

### 4. 事实清单（素材穷尽式提取，防静默丢弃）
通读全部素材，逐条提取为编号事实（F001、F002…），每条含：事实内容 + 来源（文档/页码/段落）。规则：
- 数字、阈值、流程步骤、角色职责、清单条目**一个不落**；
- 素材答不了的外部事实，列【待确认】一次性问用户；
- 必须虚构的演示数据，标 `【假设】`，禁止与真实事实混淆。

### 5. 页面名册（逐页填写，模板见 `templates/page-spec.md`）

每页一张名册卡，**七字段缺一不可**：

1. **页面任务**：本页必须为读者做的一件事（动词开头）
2. **观众动作（Audience move）**：读完这页，观众应得出的判断/采取的立场——这是论证推进的齿轮，缺了它页面就是孤岛
3. **观点**：结论式页标题（判断句）
4. **语义关系**：本页内容单元之间的关系，必标其一——`order`（流程/时序）、`link`（因果/依赖）、`parent`（总分/包含）、`membership`（并列成员）、`contrast`（对比）、`overlap`（重叠）、`none`
5. **完整内容**：⭐ **写完整成句的可用文案，不是关键词骨架**。所有论点、事实、限定词都必须出现；每个核心论点带参数/证据（机制+数字/规则）。**宁可拆页，不得删减内容来适应版式**
6. **事实来源**：用到的事实编号（F003、F007…），无来源写【假设】
7. **原型+组件**：版式选型（Stage 3 才关心）

### 6. 表达规则（语义关系决定形式——废除机械碎片化）

- **因果/论证/阐释/机制** → 用完整短句（1~2 行），保留连接词与限定词（"因为/因此/当…时/在…情况下"）
- **只有真正并列、有序、可枚举的内容**才用 `•` 列表（成员清单、步骤、参数项）
- **信息完整优先于字数**：废除"每条 ≤22 字"类限制；卡片正文允许两行完整句
- 标题仍是判断句；但正文不再强求动词开头电报体

### 7. 内容维度核对（防"该有而没有"）

| # | 维度 | 典型形态 |
|---|---|---|
| D1 | 现状与痛点 | 对比表、数据 |
| D2 | 总体/技术架构 | 分域架构图 |
| D3 | 核心流程 | 流程链 |
| D4 | 网络/部署拓扑 | 拓扑图 |
| D5 | 组织与人员 | 架构图+角色卡 |
| D6 | 培训与考核 | 流程+规则 |
| D7 | 质检/误差控制 | 阈值规则表 |
| D8 | 数据/统计/安全 | 规则表+指标 |
| D9 | 功能截图与介绍 | 截图位+证明点 |

**排除规则**：用户明确排除→记录在排除表；用户没提→必须追问；任何维度不得因"没想到"消失。

## 三、工作流程（门禁状态机）

### Stage 1 需求澄清
🚧 用户提出请求。执行：① 路由命中；② 沟通契约四问（二-1）；③ 内容模式+偏离度确认（二-2/3）；④ 维度核对表（二-7）。
✅ 契约、模式、偏离度、维度表四项经用户确认。

### Stage 2 内容策划（角色：策划者）
🚧 Stage 1 通过。执行：① 文档路由先产出**事实清单**（二-4），编辑路由先解析原稿产出事实清单（内容零丢失承诺）；② 按内容模式排页面序列；③ **逐页填写页面名册卡**（七字段，完整内容写足）；④ 汇总：名册卡 + 排除表。
✅ 用户确认名册。**绘制阶段不得回改内容；内容问题一律退回本 Stage。**

### Stage 3 设计生成（角色：绘制者）
🚧 名册确认。执行：① 读 `design-tokens.md` Pre-flight；② 按名册卡"原型+组件"逐页生成，用 `scripts/pptx_helpers.py`；③ 素材命名 `{页码}-{语义英文}.{ext}` 放 `images/`。
✅ `python scripts/validate_deck.py 文件.pptx` 通过。

**Hard rule — 内容优先于版式**：版式装不下时，第一选择是拆页/换原型，**禁止压缩完整内容去适应卡片**；确实需要精简时，回 Stage 2 与用户确认删什么。

### Stage 4 质检交付（角色：质检者，只挑错不创作）
🚧 Stage 3 通过。执行：先 P0 内容、后 P1 视觉、逐页导出目检。
✅ 交付并附「维度覆盖 + 假设数据清单 + 遗留【待确认】」。

**Hard rule — 交付文件名**：英文小写+连字符+显式后缀（如 `exam-product-intro-v2.pptx`），禁中文/空格/括号；保存后二次验证（存在+可打开+页数）再交付；提示用户"若无后缀手动补 `.pptx`"。

## 四、设计系统（承载层，不得反噬内容）

&gt; 全部令牌见 `templates/design-tokens.md`（Pre-flight 必读）；备选色板整组替换、禁止单改。

- 画布 16:9 10×5.625in；边距左右 0.5in；内容区 y 0.85~5.3in；页脚基线 y=5.44in（文档名+两位页码）
- 默认蓝金：INK #12263F / NAVY #0F2B52 / PRIMARY #0068B7 / STEEL #4A6B99 / 浅蓝阶梯 / GOLD 家族 / CYAN #37B6E6；底色 #EFF5FB；金色 ≤5%
- 字体唯一：微软雅黑；阶梯 32/17/12/9/8pt
- 骨架：淡蓝底→主蓝竖条+结论标题(+导语)→内容区→页脚

## 五、组件规范（摘要）

&gt; 参数见 `design-tokens.md` 第 5 节。徽章/卡片/对比表/流程链/架构框/指标块/结论条/截图位 8 大组件，全稿走 helpers。
&gt; **内容适配提示**：完整句正文用 9pt 文本块而非 8pt 碎片列表；规则类内容用规则表（阈值写数字）；截图配"此图证明什么"。

## 六、页面原型（摘要）

&gt; 坐标见 `templates/page-archetypes.md`。A 封面 / B 目录 / C 内容页（C1 三列卡片 C2 左右分栏 C3 上卡下表 C4 全幅流程/架构 C5 两栏对照）/ D 章节过渡 / E 数据页 / F 结尾。
&gt; **选型顺序倒过来**：先看名册卡的内容形态（对比？流程？论证？），再选原型；没有合适原型就自定义分栏，不为套原型砍内容。

## 七、质量检查清单

### 🔴 P0 · 内容（先查这层）

| # | 现象 | 做法 |
|---|---|---|
| C1 | 架构/流程/拓扑整章缺失 | 对照维度表逐行确认，排除须用户确认记录 |
| C2 | 内容骨架化：页面只有关键词无完整句 | 对照名册卡"完整内容"逐页核对，丢句即返工 |
| C3 | 观众动作缺失/页面互不衔接 | 逐页追问"这页想让观众得出什么" |
| C4 | 事实无来源、假设未标注 | 对照事实清单；所有数字必须能指到 F 编号或【假设】 |
| C5 | 语义关系错配（因果内容用并列列表） | 按二-6 表达规则逐页复查 |
| C6 | 为塞版式删减内容 | 图卡对照；内容以名册卡为准 |
| C7 | 机制页无参数（"有阈值"但无数字） | 关键章节机制+参数必须同页 |

### 🟡 P1 · 视觉

| # | 现象 | 做法 |
|---|---|---|
| V1 | 同类卡片跨页不一致 | 走 `card()/card_row()` |
| V2 | 调色板外颜色 | 必跑 `validate_deck.py` |
| V3 | 文本溢出/遮挡 | 导出图片逐页目检 |
| V4 | 混用第二中文字体 | 保留 `qn('a:ea')` 设置 |
| V5 | 页脚缺失/页码不一 | 100% 走 `page_skeleton()` |
| V6 | 截图拉伸/文字被裁 | 只用标准比例槽位 |
| V7 | 标题非结论式/金色超 2 处 | 对照 tokens 自查 |
