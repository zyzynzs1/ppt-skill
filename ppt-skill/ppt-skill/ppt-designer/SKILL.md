# PPT 设计生成技能

## 〇、三大第一性原则（置顶，凌驾一切具体规则）

1. **内容深度 &gt; 视觉统一**。首要产出是有论证深度的内容，视觉只是承载，任何视觉规则不得牺牲内容完整性。
2. **一次成型，返工最小化**。每次返工都是双倍 token 消耗——任何影响成稿的歧义（受众/风格/篇幅/偏离度/必留项/品牌约束），**必须提问澄清，禁止赌假设**。提问要合并成一轮一次问清，禁止挤牙膏式追问；但赌一个错误假设的代价远高于多问一轮。
3. **风格服务内容**。视觉风格由材料性质与受众决定，不由模型默认决定；无信号必问。

## 一、轻量路由（动手前 10 秒，命中即执行）

| 请求形态 | 路由 | 前提 | 产出 |
|---|---|---|---|
| 只有主题/模糊想法 | **主题生成**：走全部 Stage，访谈从宽 | 用户能回答受众/目的两问 | 全新 .pptx |
| 有文档/PDF/大纲/旧稿 | **文档生成**：先做素材充分性测试（见三-4），再走全部 Stage | 素材可读 | 全新 .pptx |
| 已有 .pptx 要美化/改内容 | **编辑路由**：解析原稿 → 提取事实清单（内容零丢失）→ 重构叙事 → 重排 | 原文件可打开 | 修改版 .pptx |

**Hard rule — 禁止路由菜单**：命中一行直接执行。前提不满足就明说并停止，不发明替代路线。

## 二、风格匹配（新增：先判断，后生成）

### 1. 自动判断信号（从材料与上下文中检测）

| 信号 | 判断依据 | 匹配预设 |
|---|---|---|
| 政务/考试院/国企汇报、投标响应 | 受众为政府或招标方、材料含"方案/响应/建设" | **A 藏蓝政务商务**（默认） |
| 产品发布、技术大会、互联网产品 | 材料含产品名+发布会语境、受众为市场/用户 | **B 科技深色** |
| 教育培训、校园、课程教材 | 材料含教学/课程/学员、受众为师生 | **C 清新教育** |
| 咨询报告、商业计划、路演融资 | 材料含市场/财务/ROI、受众为投资人/管理层 | **D 极简咨询** |

### 2. 询问规则（Hard rule）

- 信号明确且唯一 → 自动匹配，并在首次回复中告知「已按 XX 风格匹配」；
- 信号缺失、冲突（如政务材料但要发布会效果）或用户显式要求 → **Stage 1 提问确认，禁止自行决定**；
- 用户提供品牌 VI → VI 优先，预设仅保留结构纪律（栅格/字号阶梯/组件规则）；
- **禁止混搭两套预设**的配色与装饰语言。

预设全文见 `templates/style-presets.md`（Stage 3 前必读所匹配预设的那一节）。

## 三、内容生产线（核心，Stage 2 逐条产出）

### 1. 沟通契约
受众是谁？听完要**知道什么、相信什么、做什么**？核心信息一句话？阅读方式（演讲伴随/独立阅读）？

### 2. 内容模式（五选一，决定"怎么论证"，与视觉无关）
金字塔（结论先行，决策/投标）｜问题-解决（痛点→方案，产品介绍）｜叙事弧（情境-冲突-转折，路演）｜教学分解（概念→步骤，培训）｜中性简报（平铺完整，状态汇报）。

### 3. 材料偏离度（用户确认，默认"平衡"）
贴近原稿 / 平衡重构 / 自由重组。**铁律：事实不外扩**——原稿没有的数据/资质禁止编造。

### 4. 事实清单（素材穷尽式提取，防静默丢弃）
编号事实 F001…，每条含内容+来源（文档/页码）。数字、阈值、流程步骤、角色职责一个不落；素材答不了的列【待确认】；必须虚构的标 `【假设】`。

### 5. 内容增值三动作（防"素材堆叠"，本版核心新增）
素材只是原料，成稿必须完成三个增值动作，缺一即视为堆叠：
1. **重组**：按内容模式重排叙事（模式环节完成）；
2. **解读**：每个核心机制补一句"所以它意味着什么"——对受众的意义、相对旧做法的差别、风险被如何消除；
3. **延展（L4 洞察层）**：每章至少一处超越素材的增量观点——行业对标、风险预判、量化收益、实施建议。**标注【洞察】与事实区分，禁止伪装成素材事实**。

深度四层标准：**L1 机制 / L2 参数 / L3 数据 / L4 洞察**。关键章节必须 L1+L2 同页，每章至少一处 L4。

### 6. 页面名册（逐页填写，模板见 `templates/page-spec.md`）
七字段：①页面任务 ②观众动作 ③观点（结论式标题）④语义关系（order/link/parent/membership/contrast/overlap/none）⑤完整内容（成句文案，含增值解读，不是关键词骨架）⑥事实来源（F 编号/【假设】/【洞察】）⑦原型+组件。**宁拆页不删减**。

### 7. 表达规则（语义关系决定形式）
因果/论证/机制→完整句保留连接词；仅真并列才用 `•` 列表；信息完整优先于字数；正文允许两行完整句。

### 8. 内容维度核对（D1-D9）
现状痛点/架构/流程/拓扑/组织人员/培训考核/质检误差/数据安全/截图介绍。排除须用户确认留痕，没提到必须追问。

## 四、工作流程（门禁状态机）

### Stage 1 需求澄清（一轮问清，合并提问）
🚧 用户提出请求。执行：①路由命中；②风格信号判断（第二节）；③**合并提问清单**——受众与场合/风格确认（若信号不明）/篇幅时长/偏离度/必须保留内容/品牌VI约束/交付格式与时间/【待确认】处理授权。输出「需求确认摘要」。
✅ 用户确认摘要。**此后直至样例确认前，不再追问**。

### Stage 2 内容策划（角色：策划者）
🚧 Stage 1 通过。执行：①事实清单（三-4）；②内容增值三动作（三-5）；③按模式排页面序列+逐页填名册卡；④汇总名册+排除表+【待确认】清单。
✅ 内部自检：每章有 L4 吗？观众动作连续吗？

### Stage 2.5 样例确认（新增：返工最小化的核心闸门）
🚧 名册完成。执行：生成 **3~6 页样例**（须覆盖：封面/一个 parent 页/一个 order 或 link 页/一种风格预设的代表组件），导出给用户。
✅ 用户确认风格+深度+密度三项后，方可全量。用户修改意见在本轮一次性收集。

### Stage 3 设计生成（角色：绘制者）
🚧 样例确认。执行：①读 `design-tokens.md` Pre-flight + 所匹配预设（`style-presets.md`）；②按名册卡逐页生成；③配图按第五节策略执行；④素材命名 `{页码}-{语义英文}.{ext}`。
✅ `validate_deck.py` 通过 + **字数预算自检全过**（见第六节预算表）。

### Stage 4 质检交付（角色：质检者，只挑错不创作）
🚧 Stage 3 通过。P0 内容 → P1 视觉 → 逐页导出目检。
✅ 交付附「维度覆盖 + 【洞察】清单 + 【假设】清单 + 遗留【待确认】」。

**Hard rule — 交付文件名**：英文小写+连字符+显式后缀；保存后二次验证；提示补后缀。

## 五、配图策略（新增）

**三级配图体系**：
1. **封面主视觉**：每套预设有封面规范（A 几何色块 / B 全幅产品图或深色渐变 / C 插画或校园场景 / D 极简无图或单点大图）；
2. **章节配图**：每章首页或过渡页一张主题图；
3. **内容配图**：截图、流程图、架构图、数据图表。

**来源优先级**：①素材内图片（截图/原稿图）→ ②用户补充 → ③环境支持时联网检索或 AI 生成（注明来源；生成图优先，规避版权）→ ④**无图可用时用图形化组件替代**（流程链、架构框、图标化卡片、KPI 块），禁止放无关装饰图。

**Hard rule — 图文节奏**：纯文字页连续不得超过 2 页；每 3 页至少出现 1 个非文字视觉元素（图/表/截图/图形组件）。

## 六、设计系统与字数预算（防溢出硬约束）

&gt; 令牌见 `design-tokens.md`；风格差异见 `style-presets.md`。

**字数预算表（生成前必算，防"文字出容器"）**：
- 中文字宽 ≈ 字号(pt) × 0.0096 in；行高 ≈ 字号 × 0.015 in
- 文本块容量 = ⌊(宽−0.24)/字宽⌋ × ⌊(高−0.45)/行高⌋ 字
- deep_card 正文超预算 120% → 先降半号（9→8.5pt）；超 135% → **拆页或精简，禁止硬塞**（helpers 已内置 `text_budget` 警告）

## 七、质量检查清单

### 🔴 P0 · 内容
C1 维度整章缺失（排除须留痕）｜C2 内容骨架化（对照名册"完整内容"）｜C3 观众动作缺失/页面孤岛｜C4 事实无来源/假设未标注｜C5 语义关系错配｜C6 为塞版式删减内容｜C7 机制页无参数｜**C8 章章无 L4 洞察（=素材堆叠）**｜C9 洞察伪装成事实（未标【洞察】）

### 🟡 P1 · 视觉与风格
V1 卡片跨页不一致｜V2 调色板外颜色｜V3 文字溢出/出容器（预算表核对）｜V4 混用第二中文字体｜V5 页脚缺失｜V6 截图变形｜V7 标题非结论式/金色超量｜**V8 风格信号错配（政务材料配发布会深色等）**｜**V9 纯文字页连超 2 页（缺配图节奏）**
